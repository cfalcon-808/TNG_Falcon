TRAIN_FALCON.PY DETAILED GUIDE
Version Context: train_falcon.py (mppo_train3.0) + env_tng_abc.py (env6.0)
Last Updated: 2026-02-16

============================================================
1) PURPOSE OF train_falcon.py
============================================================
train_falcon.py is a sweep-style training runner for MaskablePPO.

It runs an experiment suite made of one or more named VARIATIONS.
Each variation can be:
- A baseline/default run
- A single-phase run with config overrides
- A multi-phase curriculum that continues the same model across phases

Core pipeline per phase:
1. Build vectorized envs with SubprocVecEnv
2. Apply ActionMasker to enforce legal action sampling
3. Train MaskablePPO for phase timesteps
4. Save periodic checkpoints
5. Log metrics to TensorBoard
6. Continue into next phase (if configured)

============================================================
2) WHAT YOU MUST CONFIGURE (TOP OF FILE)
============================================================
Edit these sections in train_falcon.py before running.

A) Identity and matchup config
- EXPERIMENT_NAME
- LEARNER_ROLE: GOAT_LEARNER or TIGER_LEARNER
- OPPONENT_AI:
  For goat learner:
  - OPP_TIGER_GREEDY
  - OPP_TIGER_SMART

  For tiger learner:
  - OPP_GOAT_RANDOM
  - OPP_GOAT_MODEL

- MIX_PROB:
  - None = fixed opponent
  - Float in [0,1] = per-reset probabilistic mixing

B) Version tags / output labels
- ALGO_TAG
- ENV_VER
- MODEL_VER

C) Run scale and hardware
- DEVICE_MODE: "cpu" or "gpu"
- DEBUG_MODE
- TIMESTEPS
- NUM_CPU
- SEED

D) PPO hyperparameters
- GAMMA
- LEARNING_RATE
- ENT_COEF
- N_STEPS, BATCH_SIZE, N_EPOCHS (auto-selected by DEVICE_MODE block)

E) Save/resume controls
- CHECKPOINTS_PER_RUN
- RESUME_MODEL_PATH (None, .zip path, or directory containing zips)
- GOAT_MODEL_PATH (used only if opponent goat model is selected)

F) Variation definitions
- VARIATIONS dict (the main thing controlling what gets trained)

============================================================
3) HOW MATCHUPS ARE RESOLVED
============================================================
train_falcon.py uses a unified OPPONENT_AI setting, then resolves it by learner role.

GOAT_LEARNER:
- OPP_TIGER_GREEDY -> tiger_ai=greedy
- OPP_TIGER_SMART  -> tiger_ai=smart

TIGER_LEARNER:
- OPP_GOAT_RANDOM -> goat_opponent_ai=random
- OPP_GOAT_MODEL  -> goat_opponent_ai=model

If you pass an invalid combination, the script exits early.

============================================================
4) WHAT HAPPENS WHEN YOU RUN
============================================================
Command:
python train_falcon.py

Startup behavior:
1. Prints experiment summary and variation cores
2. Iterates each variation in VARIATIONS
3. For each variation:
   - normalize_phases(...) converts config into a phase list
   - resolve_variation_core(...) determines logging/model folder core tag
   - run_single_variation(...) trains one phase at a time

Per-phase behavior:
1. Resolve phase timesteps/opponent/mix/reward overrides/checkpoint frequency
2. Build NUM_CPU workers using make_env(...)
3. Wrap each env with Monitor/TigerMixWrapper/GoatMixWrapper, then ActionMasker
4. Create or reuse model
5. Learn for phase timesteps
6. Close vec env

End of variation:
- Compute aggregate stats (goat/tiger/max timeout/repeat timeout rates)
- Save final model with phase suffix _p{last_phase_index}

============================================================
5) OUTPUT LOCATIONS
============================================================
TensorBoard logs:
artifacts/logging/train/{ALGO_TAG}/{CORE}/{EXPERIMENT_NAME}/

Model artifacts:
artifacts/models/train/{ALGO_TAG}/{CORE}/{EXPERIMENT_NAME}/

Typical outputs:
- Checkpoints:
  cp_{ALGO}_{CORE}_{variation}_*.zip
- Final model:
  {ALGO}_{CORE}_{variation}_p{phase}.zip

6) TENSORBOARD METRICS TO WATCH
============================================================
1.episode_stats/*
- episode_index
- episodes_total_done
- cumulative goat/tiger/timeout/stall rates

2.window_stats/*

7) DETAILED VARIATION GUIDE
============================================================
This is the most important section for experiment design.

A variation is one key-value entry in VARIATIONS.
The key is the variation name.
The value controls how it runs.

------------------------------------------------------------
7.1 Variation formats
------------------------------------------------------------
Format A: None (baseline)
Example:
VARIATIONS = {
    "baseline": None,
}

Meaning:
- Uses global TIMESTEPS, OPPONENT_AI, MIX_PROB, CHECKPOINTS_PER_RUN
- Uses default env reward setup (no reward override dict)

Format B: Single-phase dict
Example:
VARIATIONS = {
    "no_bubble": {
        "timesteps": 30_000_000,
        "opponent_ai": OPP_TIGER_SMART,
        "mix_prob": None,
        "checkpoints_per_run": 12,
        "bubble": 0.0,
    }
}

Meaning:
- One phase only
- Special control keys are parsed directly
- Remaining keys are treated as reward overrides (reward_weights)

Format C: Multi-phase curriculum (list of dicts)
Example:
VARIATIONS = {
    "goat_GT_to_ST_to_mix": [
        {"timesteps": 20_000_000, "opponent_ai": OPP_TIGER_GREEDY},
        {"timesteps": 20_000_000, "opponent_ai": OPP_TIGER_SMART},
        {"timesteps": 20_000_000, "opponent_ai": OPP_TIGER_SMART, "mix_prob": 0.3},
        {"timesteps": 20_000_000, "opponent_ai": OPP_TIGER_SMART, "mix_prob": 0.5},
    ]
}

Meaning:
- Trains continuously across phases on the same model
- Each phase can change opponent/mix/timesteps/reward overrides

------------------------------------------------------------
7.2 Recognized per-phase control keys
------------------------------------------------------------
These keys are consumed as phase controls (not reward terms):
- timesteps
- tiger_ai (legacy alias)
- opponent_ai (preferred)
- mix_prob
- checkpoints_per_run
- goat_model_path
- reward_weights (for explicit multi-phase style)

If you use single-phase dict format:
- Any keys not in that control-key list become reward overrides automatically.

If you use multi-phase list format:
- Use reward_weights explicitly for clarity:
  {"timesteps": ..., "opponent_ai": ..., "reward_weights": {...}}

------------------------------------------------------------

------------------------------------------------------------
7.4 Practical variation patterns
------------------------------------------------------------
Pattern 1: Baseline + single ablations
VARIATIONS = {
    "baseline": None,
    "no_bubble": {"bubble": 0.0},
    "no_block": {"block_tiger": 0.0},
    "no_center": {"center": 0.0},
}

Pattern 2: Magnitude sweep
VARIATIONS = {
    "bubble_025": {"bubble": 0.25},
    "bubble_050": {"bubble": 0.50},
    "bubble_100": {"bubble": 1.00},
    "bubble_200": {"bubble": 2.00},
}

Pattern 3: Robustness curriculum (goat learner)
VARIATIONS = {
    "robust_goat_curriculum": [
        {"timesteps": 30_000_000, "opponent_ai": OPP_TIGER_GREEDY},
        {"timesteps": 20_000_000, "opponent_ai": OPP_TIGER_SMART},
        {"timesteps": 20_000_000, "opponent_ai": OPP_TIGER_SMART, "mix_prob": 0.3},
        {"timesteps": 20_000_000, "opponent_ai": OPP_TIGER_SMART, "mix_prob": 0.5},
    ]
}

Pattern 4: Tiger learner with mixed goat opponents
VARIATIONS = {
    "tiger_vs_mixed_goats": [
        {
            "timesteps": 30_000_000,
            "opponent_ai": OPP_GOAT_RANDOM,
            "mix_prob": 0.4,
            "goat_model_path": "artifacts/models/train/.../best_goat.zip",
            "reward_weights": None,
        }
    ]
}

------------------------------------------------------------
7.5 How to add a new variation safely
------------------------------------------------------------
Checklist:
1. Pick unique variation name
2. Decide single-phase vs multi-phase
3. Set timesteps per phase
4. Set opponent_ai and optional mix_prob
5. Add only valid reward/knob keys
6. Keep checkpoints_per_run high enough for recovery (for long runs)
7. Run one short debug trial first (small timesteps)

Recommended debug pass before long run:
- DEBUG_MODE = True
- TIMESTEPS small (for example 2_000_000 or less)
- NUM_CPU reduced if needed
- Single variation first

------------------------------------------------------------
7.6 Common mistakes
------------------------------------------------------------
- Using GOAT opponent enums while LEARNER_ROLE is GOAT (or vice versa)
- Forgetting goat_model_path when using OPP_GOAT_MODEL
- Overloading a single run with too many changed knobs at once
- Running huge timesteps before validating logs/checkpoints on a short run
- Assuming mix_prob changes model architecture (it only changes opponent sampling)

============================================================
8) RESUME TRAINING NOTES
============================================================
RESUME_MODEL_PATH supports:
- Exact .zip file
- Directory (latest .zip in dir is picked)

Behavior:
- Phase 0 is treated as continuation when resume model is loaded
- reset_num_timesteps=False in continuation flow
- Useful for extending prior runs or continuing curriculum branches
