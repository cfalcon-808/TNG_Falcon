1. Scope and Conventions
------------------------
This document describes the reward logic currently implemented in:
- env_tng_abc.py
- train_abc.py (for goat reward-component TensorBoard logging)

All formulas and magnitudes below use the current default knobs in
env_tng_abc.py.

Default high-impact knobs
-------------------------
- REWARD_GOAT_WIN         = 3.2
- REWARD_TIGER_WIN        = -3.2
- REWARD_TIGER_CAPTURE    = 0.35
- REWARD_TIGER_WIN_BONUS  = 3.2
- REWARD_TIGER_LOSS_PENALTY = 3.2
- REWARD_STEP             = -0.001
- REWARD_GOAT_EATEN       = -0.35
- MAX_TIMEOUT_SCALE       = 1.5
- REPEAT_STALL_SCALE      = 1.25
- MAX_TURNS               = 100
- MOVE_STEP_BASE          = -0.01
- MOVE_STEP_SLOPE         = -0.01
- MOVE_STEP_MIN           = -0.6
- GOAT_WIN_TURN_DECAY     = 0.01
- REWARD_BLOCK_TIGER      = 0.08
- REWARD_BUBBLE_SPACE     = 0.02
- REWARD_CLUSTER_TIGERS   = 0.02
- REWARD_CENTER_GOAT      = 0.03
- REWARD_CENTER_TIGER     = -0.03
- NEAR_LOCK_BONUS         = 0.05
- MOBILITY_BACKSLIDE_SCALE = 0.5
- GOAT_SHAPING_DECAY_BASE = 0.95
- REWARD_REPEAT_STATE     = -0.5
- MAX_REPEATS             = 4

Conventions used in the tables
------------------------------
- "Per-step" means the largest single-step contribution that family can make.
- "Episode envelope" means a safe default-code envelope over a 100-turn episode.
- Some episode envelopes are theoretical maxima, not jointly reachable in one
  real game. They are used to compare scale, not to claim all rewards can be
  collected at once.
- Goat positive decay-based shaping uses:
    decay_mult = GOAT_SHAPING_DECAY_BASE ** move_steps
- Current goat code rewards positive shaping during:
    - 14 placing-phase reward steps with no decay
    - 86 phase==1 reward steps with decay factors 0.95 ** m for m=0..85
  This yields the geometric sum:
    sum(0.95 ** m for m in 0..85) = 19.757194
- Current goat full-episode step penalty over 100 turns is:
    15 placing turns + 85 moving turns = -33.315
- Safe graph-level bound used for mobility-delta envelopes:
    abs(delta_moves) <= 12
- Positive goat tanh-shaped families asymptotically cap at:
    coefficient * decay_mult


2. Goat Reward Rundown
----------------------
Goat reward families
--------------------
1) Outcome family
- Goat win:
    REWARD_GOAT_WIN - GOAT_WIN_TURN_DECAY * turns
- Tiger win by capture threshold:
    REWARD_TIGER_WIN
- Max timeout:
    REWARD_TIGER_WIN * MAX_TIMEOUT_SCALE
- Repeat timeout:
    REWARD_TIGER_WIN * REPEAT_STALL_SCALE

Behavior:
- Goat win is the primary positive terminal outcome.
- All non-win terminal outcomes are strictly bad.
- Positive shaping is not added on tiger-win, max-timeout, or repeat-timeout
  terminal steps.

2) Tempo family
- Placing phase:
    REWARD_STEP
- Moving phase:
    max(MOVE_STEP_BASE + MOVE_STEP_SLOPE * move_steps, MOVE_STEP_MIN)

Behavior:
- Small placing penalty, then an increasingly negative moving penalty.
- This is the main "finish the game" pressure.

3) Containment family
- Near-lock:
    NEAR_LOCK_BONUS * decay_mult
- Positive block:
    abs(REWARD_BLOCK_TIGER) * tanh(delta_moves) * decay_mult
    only when delta_moves > 0
- Negative block backslide:
    abs(REWARD_BLOCK_TIGER) * MOBILITY_BACKSLIDE_SCALE * delta_moves
    only when delta_moves < 0
- Bubble:
    REWARD_BUBBLE_SPACE * tanh(delta_bubble) * decay_mult
    only when delta_bubble > 0
- Cluster:
    REWARD_CLUSTER_TIGERS * tanh(delta_spread) * decay_mult
    only when delta_spread > 0

Behavior:
- Positive containment rewards now saturate and decay.
- Negative mobility backslide remains linear and does not decay.
- This family helps the goat trap tigers, but should not dominate winning.

4) Opening structure family
- Center control:
    center_score
    only when phase == 0 in the goat reward path

Behavior:
- Goat center shaping now applies only in placing phase.
- This is intentionally an opening-setup incentive, not a move-phase farming term.

5) Material family
- Goat eaten:
    REWARD_GOAT_EATEN * goats_eaten_this_turn

Behavior:
- Strong negative signal for allowing tiger captures.

6) Anti-cycling family
- Non-terminal repeat penalty:
    REWARD_REPEAT_STATE * prev_count^2
- Repeat timeout terminal penalty:
    REWARD_TIGER_WIN * REPEAT_STALL_SCALE

Behavior:
- Repeated board states are punished quadratically.
- Repeating too often escalates to a terminal repeat-timeout.

7) Invalid-action family
- Invalid soft:
    REWARD_INVALID_SOFT
- Invalid hard:
    REWARD_INVALID_HARD

Behavior:
- Safety rails. These should be rare with action masking.


3. Goat Reward Magnitude Table
------------------------------

Goat reward family magnitudes
-----------------------------
| Family | Formula / terms | Per-step best | Per-step worst | 100-turn episode envelope | Notes |
| ------ | --------------- | ------------- | -------------- | ------------------------- | ----- |
| Outcome: goat win | 3.2 - 0.01 * turns | +3.19 at turn 1 | +2.20 at turn 100 | one-time terminal only | Winning later is still good, but slightly discounted |
| Outcome: tiger win | REWARD_TIGER_WIN | -3.2 | -3.2 | one-time terminal only | No positive shaping survives this terminal step |
| Outcome: max timeout | REWARD_TIGER_WIN * 1.5 | -4.8 | -4.8 | one-time terminal only | Strictly worse than a normal loss |
| Outcome: repeat timeout | REWARD_TIGER_WIN * 1.25 | -4.0 | -4.0 | one-time terminal only | Strictly worse than a normal loss |
| Tempo: placing step | REWARD_STEP | -0.001 | -0.001 | -0.015 over 15 turns | Applies before move phase begins |
| Tempo: moving step | max(-0.01 - 0.01 * move_steps, -0.6) | -0.01 | -0.6 | -33.300 over 85 moving turns | Full-step family total including placing = -33.315 |
| Containment: near-lock | 0.05 * decay_mult | +0.05 | 0.0 | +1.687860 | Episode envelope assumes it fires on all 14 placing reward steps and all 86 decayed phase==1 steps |
| Containment: block positive | 0.08 * tanh(delta_moves) * decay_mult | about +0.08 * decay_mult | 0.0 | +2.700575 | Saturates at the coefficient, then decays |
| Containment: block backslide | 0.08 * 0.5 * delta_moves, delta_moves < 0 | 0.0 | -0.48 using delta_moves = -12 | about -48.0 theoretical | Safe graph-level envelope, not a realistic every-step trajectory |
| Containment: bubble | 0.02 * tanh(delta_bubble) * decay_mult | about +0.02 * decay_mult | 0.0 | +0.675144 | Positive only, saturated and decayed |
| Containment: cluster | 0.02 * tanh(delta_spread) * decay_mult | about +0.02 * decay_mult | 0.0 | +0.675144 | Positive only, saturated and decayed |
| Opening structure: center | center_score during goat phase==0 only | +0.15 | -0.09 | +2.10 best, -1.26 worst | Per-step best = 5 goat centers; per-step worst = 3 tiger centers |
| Material: goat eaten | -0.35 * goats_eaten_this_turn | 0.0 | -0.35 | -2.10 total | Tigers need 6 captures to win |
| Anti-cycling: repeat penalty | -0.5 * prev_count^2 | 0.0 | -2.0 non-terminal | -2.5 over one repeat chain before terminal | Chain is 0, -0.5, -2.0, then repeat-timeout terminal |
| Invalid soft | -0.05 | -0.05 | -0.05 | terminal on invalid step | Rare under masking |
| Invalid hard | -1.0 | -1.0 | -1.0 | terminal on invalid step | Rare under masking |

Goat family-level interpretation
--------------------------------
- Outcome family:
    Best case = fast goat win
    Worst case = max timeout (-4.8)
- Tempo family:
    Always negative; strongest anti-stall pressure in the reward
- Containment family:
    Positive containment is now capped and decayed
    Negative mobility backslide can still be large if the goat opens tiger mobility
- Opening structure family:
    Only supports the opening now
- Material family:
    Caps at -2.1 over an episode because tiger win by captures occurs at 6 eaten goats
- Anti-cycling family:
    Can stack meaningfully even before the terminal repeat-timeout


4. Tiger Reward Rundown
-----------------------
Tiger reward families
---------------------
1) Outcome family
- Tiger win by captures:
    REWARD_TIGER_WIN_BONUS
- Tiger win by no legal goat move:
    REWARD_TIGER_WIN_BONUS
- Goat win by immobilizing tigers:
    -REWARD_TIGER_LOSS_PENALTY
- Max timeout:
    -REWARD_TIGER_LOSS_PENALTY * MAX_TIMEOUT_SCALE

Behavior:
- Tiger wants a decisive win.
- Timeouts are punished more harshly than a standard tiger loss.

2) Tempo family
- Every tiger step:
    REWARD_STEP

Behavior:
- Small per-turn penalty to discourage stalling.

3) Material family
- Tiger capture reward:
    REWARD_TIGER_CAPTURE * goats_eaten_this_turn

Behavior:
- Direct reward for eating goats.
- This is the clearest non-terminal path toward a tiger win.

4) Mobility family
- Mobility shaping:
    abs(REWARD_BLOCK_TIGER) * delta_moves

Behavior:
- Positive when tiger move count increases after the tiger action.
- Negative when the tiger reduces its own future mobility.
- This family is currently linear, not saturated, and not decayed.

5) Opening structure family
- Center control:
    center_score
    only when phase == 0 in the tiger reward path

Behavior:
- Early positional incentive only.
- Important implementation detail:
    tiger center_score is currently built from abs(REWARD_CENTER_GOAT),
    not REWARD_CENTER_TIGER.
    That means changing REWARD_CENTER_TIGER does not affect tiger learner
    center shaping.

6) Invalid-action family
- Invalid soft:
    REWARD_INVALID_SOFT
- Invalid hard:
    abs(REWARD_INVALID_HARD)

Behavior:
- Safety rails. These should be rare with action masking.
- Current invalid-hard tiger return is positive because the code takes abs().

7) Repeat-timeout note
- Tiger reward currently has no dedicated repeat-timeout branch.
- The tiger transition path does not currently add repeat-state penalties.

Tiger family-level interpretation
---------------------------------
- Outcome family:
    Best case = decisive tiger win (+3.2)
    Worst case = max timeout (-4.8)
- Tempo family:
    Very light anti-stall pressure compared with the goat moving-phase penalty
- Material family:
    Strong, direct signal aligned with capture-based tiger wins
- Mobility family:
    Largest non-terminal tiger shaping family in raw scale
    Because it is linear, it can dominate if left unchecked in future tuning
- Opening structure family:
    Early-game only, smaller than the mobility family


6. Reading PPO Train Metrics
----------------------------
The TensorBoard `train/*` plots are PPO optimizer-health metrics. They are
useful for diagnosing how the policy is learning, but they are not direct
success metrics. The main task-success metrics are still:
- goat_win_rate
- tiger_win_rate
- max_timeout_rate
- repeat_timeout_rate
- episode length

How to interpret the most important PPO train plots
---------------------------------------------------

approx_kl
- What it is:
    How far the updated policy moved from the previous policy in one PPO update.
- Higher usually means:
    The optimizer is making larger policy shifts.
- What to watch for:
    Persistently higher KL in one run can mean PPO found a strong optimization
    direction, but not necessarily a good one.

clip_fraction
- What it is:
    Fraction of samples where PPO clipping activated.
- Higher usually means:
    More updates are pushing against PPO's trust-region guardrail.
- What to watch for:
    If one run has much higher clip_fraction, that run is under stronger update
    pressure and may be exploiting a sharp or unstable reward signal.

clip_range
- What it is:
    The PPO clip hyperparameter.
- What to watch for:
    Usually constant. Only useful to confirm two runs used the same PPO setting.

entropy_loss
- What it is:
    A proxy for policy entropy behavior.
- Less negative over time usually means:
    The policy is becoming more confident and less random.
- What to watch for:
    Similar entropy curves with very different outcomes usually means the issue
    is not exploration level, but objective alignment.

explained_variance
- What it is:
    How well the value function predicts returns.
- Higher is generally better:
    Near 1 means the critic explains returns well.
- What to watch for:
    Good explained variance does not prove the policy is good. It only means
    the reward structure is predictable enough for the critic to model.

loss
- What it is:
    Aggregate PPO training loss.
- What to watch for:
    Use only as a rough stability indicator. By itself it is not a reliable
    measure of policy quality.

policy_gradient_loss
- What it is:
    Core policy update signal.
- Larger magnitude usually means:
    Stronger policy-gradient pressure.
- What to watch for:
    If this gets larger while outcome metrics worsen, PPO may be aggressively
    optimizing the wrong thing.

value_loss
- What it is:
    Critic prediction error.
- Lower is generally cleaner:
    The value network is fitting returns more easily.
- What to watch for:
    Higher or noisier value_loss often means the return structure is messier,
    more exploitable, or less consistent.

learning_rate
- What it is:
    The optimizer learning rate schedule.
- What to watch for:
    Usually fixed in these runs. Mostly used to verify runs are comparable.

Practical interpretation for this project
-----------------------------------------
- If win rate rises and timeout rate falls:
    higher KL or clip_fraction can be acceptable.
- If episode reward rises but timeout rate also rises:
    the policy may be farming shaping rather than converting wins.
- If value_loss is lower and outcome metrics improve:
    the reward signal is probably cleaner and easier to optimize.
- If one opponent produces much higher KL, clip_fraction, and value_loss than
  another opponent:
    that usually means the policy is finding a more exploitable strategy path
    against that opponent.

Recommended reading order in TensorBoard
----------------------------------------
1. Read outcome metrics first:
    goat_win_rate, tiger_win_rate, max_timeout_rate, repeat_timeout_rate
2. Then read episode-level behavior:
    ep_len_mean, ep_rew_mean
3. Then use PPO train metrics to explain why those curves look the way they do:
    approx_kl, clip_fraction, policy_gradient_loss, value_loss, explained_variance


7. Key Takeaways
----------------
1) Goat reward is now much more outcome-first than before
- non-win terminals are strictly bad
- positive containment is capped and decayed
- center control is opening-only

2) Goat tempo pressure is currently very strong
- the full 100-turn step-penalty envelope is -33.315
- that is much larger in raw scale than any one terminal outcome

3) Goat containment is now bounded by design
- near-lock full-episode envelope: +1.687860
- block full-episode saturated envelope: +2.700575
- bubble full-episode saturated envelope: +0.675144
- cluster full-episode saturated envelope: +0.675144

4) Tiger reward is still more linearly shaped than goat reward
- mobility is linear
- center shaping is placing-only
- there is no tiger repeat-state shaping path today

5) If reward curves look strange, compare families first
- goat:
    terminal vs tempo vs containment vs repeat
- tiger:
    terminal vs capture vs mobility
