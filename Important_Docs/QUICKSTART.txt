============================================================
TIGERS & GOATS - FALCON BRANCH
QUICKSTART WORKFLOW (ABC TRAINING RUNNER)
============================================================

This guide walks new users through:
  - environment setup
  - running a training experiment (suite of variations)
  - evaluating and debugging trained models

----------------------------------------------------------------
0) Prerequisites
----------------------------------------------------------------
- Python 3.10+ recommended
- NVIDIA GPU optional but preferred
- Install PyTorch matching your CUDA version if using GPU

----------------------------------------------------------------
1) Create a virtual environment & install dependencies
----------------------------------------------------------------
    python -m venv .venv
    .\.venv\Scripts\activate          # Windows PowerShell
    pip install --upgrade pip
    pip install -r docs/requirements.txt

    # Then install the correct PyTorch wheel for your CUDA version:
    # https://pytorch.org/get-started/locally/

----------------------------------------------------------------
2) Project layout (key files)
----------------------------------------------------------------
    env_tng_abc.py
        Unified Gymnasium environment.
        Receives tuning knob overrides from the training runner.

    train_abc.py
        Training runner.
        Executes ONE EXPERIMENT (suite) consisting of multiple VARIATIONS.
        Supports flat single-phase dicts or flat multi-phase curricula.

    eval_falcon.py
        Evaluation & debugging tool.
        Runs deterministic rollouts and batch statistics.

    tng_GUI_falcon.py
        Tkinter GUI for live play, quick model smoke tests, and replay browsing.

    artifacts/
        {EXPERIMENT_NAME}/
          meta/
          tb/
          checkpoints/
          models/
          eval/
          logs/

----------------------------------------------------------------
3) Run a fast training experiment (smoke test)
----------------------------------------------------------------
1) Open train_abc.py and set:
        EXPERIMENT_NAME = "my_first_experiment"
        OPPONENT_AI     = OPP_TIGER_GREEDY   # or OPP_TIGER_SMART
        DEBUG_MODE      = True               # shorter runs

2) Define variations (single-phase example):
        VARIATIONS = {
            "defaultSettings": None
        }

   Single-phase with direct knob overrides:
        VARIATIONS = {
            "no_bubble": {
                "timesteps": 20_000_000,
                "opponent_ai": OPP_TIGER_SMART,
                "REWARD_BUBBLE_SPACE": 0.0,
                "BASE_TIGER_CAPTURE_BIAS": 0.8,
            }
        }

   Multi-phase example (greedy to smart to mixed tiger):
        VARIATIONS = {
            "greedy_to_smart_mix": [
                {"timesteps": 10_000_000, "opponent_ai": OPP_TIGER_GREEDY},
                {"timesteps": 10_000_000, "opponent_ai": OPP_TIGER_SMART},
                {"timesteps": 30_000_000, "opponent_ai": OPP_TIGER_SMART, "mix_prob": 0.3},
                {"timesteps": 30_000_000, "opponent_ai": OPP_TIGER_SMART, "mix_prob": 0.5},
            ],
        }

3) Run:
        python train_abc.py

4) Outputs:
        Models:
          artifacts/{EXPERIMENT_NAME}/models/
        Logs:
          artifacts/{EXPERIMENT_NAME}/tb/

----------------------------------------------------------------
4) Monitor training with TensorBoard
----------------------------------------------------------------
    tensorboard --logdir artifacts --port 6006

Each variation appears as its own phase-tagged run under the experiment folder.

----------------------------------------------------------------
5) Evaluate or debug a trained model
----------------------------------------------------------------
Recommended (explicit model path):
    python eval_falcon.py battle artifacts\baselineGoatTrainingV3\models\final_goat_vs_smart_tiger_50M_20260320_231909_phase_01.zip

Defaults:
    MODE (optional): normal  -> greedy tiger (default)
                     battle  -> smart tiger
    MODEL_PATH (optional): explicit path to a trained .zip model

Evaluation modes include:
  - step-by-step debug episodes
  - batch evaluation (win / timeout rates)
  - action masks + decoded moves
  - optional ASCII board rendering

Logs are written under:
    artifacts/logging/eval_debug/

----------------------------------------------------------------
6) Common configuration knobs
----------------------------------------------------------------
train_abc.py:
    OPPONENT_AI         = OPP_TIGER_GREEDY | OPP_TIGER_SMART
    MIX_PROB            = None or float in [0, 1]
    DEBUG_MODE          = True / False
    TIMESTEPS           = adjust for runtime
    VARIATIONS          = flat single-phase dicts or multi-phase curricula
    DEVICE_MODE         = "gpu" or "cpu"
    NUM_CPU             = parallel env workers
    CHECKPOINTS_PER_RUN = number of checkpoints per phase
    RESUME_MODEL_PATH   = model zip or directory of saved zips

eval_falcon.py:
    N_DEBUG_EPISODES
    N_EVAL_GAMES
    PRINT_DEBUG_TO_CONSOLE

----------------------------------------------------------------
7) If something breaks
----------------------------------------------------------------
- Confirm the virtualenv is active
- Verify PyTorch matches your CUDA version
- Delete old TensorBoard logs if the dashboard is cluttered
- Run eval_falcon.py with an explicit model path to confirm env loads cleanly

----------------------------------------------------------------
Summary
----------------------------------------------------------------
- One EXPERIMENT = a suite of VARIATIONS
- One VARIATION  = one PPO training run (phase-aware if you use lists)
- One CORE       = one learner/opponent matchup
- Same environment file for all runs

Train with train_abc.py,
inspect with TensorBoard,
and debug/evaluate with eval_falcon.py (or the GUI for quick visuals).
