ENV6.0 CHANGE OVERVIEW (from env5.0)
Date: 2026-02-16

Summary
- env6.0 standardizes the project on native Discrete(115) actions end-to-end.
- Flatten wrappers were removed from training, evaluation, and GUI paths.
- The environment now uses stricter step semantics, cleaner info payloads, and a centralized reward hook.

1) env_tng_abc.py (new env6.0 environment)
- Introduced and positioned as the primary environment replacing env5.0 usage.
- Action interface is native Discrete(115) with encode/decode helpers:
  - encode_action(pos, dir_code)
  - decode_action(action)
- Internal goat valid move representation moved to flat action ids (0..114).
- get_action_mask() updated to support flat internal representation and remain learner-role aware.
- step() routing now uses transition functions with reward post-processing through reward_fn:
  - reward_fn defaults to sparse_reward
  - allows custom reward injection without changing transition logic
- Added explicit max_turns constructor argument with validation:
  - max_turns must be > 0
  - synchronized with MAX_TURNS knob
- Added strict info schema fields each step:
  - reason, winner, goat_action, goat_decoded, tiger_move,
    phase, goats_eaten, goats_placed, turn_counter
- Termination semantics cleaned up:
  - invalid actions and timeouts now truncate episodes
  - game outcomes terminate episodes
- Added tiger policy invariant:
  - if tiger policy returns None while legal tiger moves exist, raise RuntimeError
- Removed stale legacy reward reason handling and cleaned stale comments.
- Updated header/flower box to Version env6.0.

2) train_falcon.py
- Environment import switched from env_tng_falcon to env_tng_abc.
- FlattenTnGActionWrapper import removed.
- Environment wrapping chain simplified:
  - Before: BaseEnv -> (Monitor/TigerMixWrapper) -> FlattenWrapper -> ActionMasker
  - Now:    BaseEnv -> (Monitor/TigerMixWrapper) -> ActionMasker
- Training now relies on the env's native Discrete(115) action space + masks.

3) eval_falcon.py
- Environment import switched to env_tng_abc.
- Flatten wrapper import and usage removed in both debug and eval env builders.
- Debug/eval pipelines now run directly on native Discrete(115) + ActionMasker.
- Header/comments updated to reflect no-wrapper action handling.

4) tng_GUI_falcon.py
- Environment import switched to env_tng_abc.
- Flatten wrapper import and usage removed.
- Live and record env setup now uses base env directly.
- Goat move validation updated from pair-membership checks to flat-mask checks:
  - Added helper: _is_flat_goat_action_valid(action_flat)
  - Click handling and highlighting now validate using current action mask.
- Model move path uses base env action mask directly.
- Stale wrapper/flatten comments were updated or removed.

5) Relationship to env_tng_falcon.py (env5.0 baseline)
- env_tng_falcon.py remains in the repo as historical baseline.
- Active integration path for train/eval/gui is now env_tng_abc.py (env6.0).
- Core migration intent:
  - one native action format across stack
  - less wrapper complexity
  - cleaner step/info/reward plumbing

6) Expected behavior impact
- Action plumbing is more consistent across scripts and UI.
- Invalid actions and timeouts are treated as truncations rather than game-result terminations.
- Info payload is more uniform for logging, debugging, and analysis.
- Reward logic is easier to evolve through reward_fn/sparse_reward isolation.

7) Notes
- Existing models trained with masked Discrete actions remain compatible with the new no-wrapper pipeline.
- If any old utility expected pair-style valid_moves directly, it should be updated to either:
  - use get_action_mask(), or
  - decode flat valid moves via decode_action().
